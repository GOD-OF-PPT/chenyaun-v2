## 2. 优先级与状态定义

- P0：影响数据、授权、运行或交付真实性的阻断项。当前没有足够证据新判定存档故障；保留必测要求。
- P1：直接影响塑料感、核心战斗理解或第一段旅程，应在品质样片内处理。
- P2：提升持续内容品质，在样片验证方向后扩展。
- 已观察：来自实际界面或代码事实。设计判断：由证据提出的体验解释。待验证：目前不足以认定缺陷。

估算 S/M/L 只表示相对工作量：S=单一文档/组件，M=多个状态或少量资产，L=新资产流程或跨系统体验。它不是工期承诺，须在样片试制后重新估算。

## 4. 应保留的基础

- 破庙与洞府已经具备可用于确定环境情绪的背景资产，不必在方向未验证前全量推倒重做。
- 已有连击、爆剑、闪避、剑印及多种反馈代码；优先明确其用途、表现与教学，再判断是否需要新增机制。
- 当前抽查看到了明确的目标追踪、初始操作提示、失败后的主动选择；应改进语境与信息层级，而不是简单删除。
- 存档、经济和安全的历史修复有独立价值。品质升级不得为视觉简化而取消保护或隐藏失败。
- （复核补充）**死亡复盘弹窗**（R04）：列出致死来源、受击次数、本战未使用仙葫/识破的数据提示和两条行动建议，提供三项需主动选择的恢复方式，并写明“所有战利品均已保全”。这已经接近 PLAY-04 “失败应提示可执行改进”的要求，可作为其他失败与结算界面的模板。
- （复核补充）**a11y 设置**（`chenyuan_a11y_v20`）：震屏、顿帧 0–150%，减弱动效（跟随系统偏好），色盲几何符文（◆金·反 / ▲红·闪 / 〰青·跃 / ⬢擒·拼），提示密度三档，分层景深开关。UX-04、AUD-02 和降低动态效果的实施应在此基础上扩展，不要另建一套。
- （复核补充）**敌招读招体系**：普通怪按金招（识破）、红危（极限闪避）、下段危（Z 踏剑）、擒拿（拼刀）四类轮换，有文字和符文双编码；三兵种小队和章节变种（金盾、镜反、绕背等）已在 PR #24 / #28 落地。PLAY-01 应先评估这套体系的可读性，而不是从零设计。
- （复核补充）**可复用的验证工具**：`scripts/eval-combat-matrix.mjs`（84 组策略矩阵）、`scripts/audit-economy.mjs`、游戏内试玩遥测导出（`#btn-export-playtest-telemetry`，含 `pedestalChoiceSec` 等字段），以及 F3 帧耗时浮层。

## 5. 推荐处理顺序

1. 冻结实际交付基线，处理 GAP-12，并补性能、声音和核心战斗的调查证据。
2. 用 GAP-01/02/04 制作目标画面、动作样片和战斗信息层级样片，先证明视觉与动作方向。
3. 通过 GAP-08/09 验证战斗与成长；让美术资产服务确定的动作和决策。
4. 用 GAP-03/05/06/10 串联救人、返回、整备与再次出行。
5. 完成 GAP-07/11/13/14 的可读性、声音、性能、兼容与交付复核，再决定全游戏推广。

> [!IMPORTANT]
> **复核后的建议顺序**：GAP-12 和 GAP-06 已关闭，第 1 步改为“登记已有基线（证据包与 Q7 数据）并补 GPU 帧时间与声音试听”。在美术样片之前，先做一组**低成本、高收益的首战修复**（GAP-15/16/18/20，均为 S 级）。这几项直接改善每位新玩家前 60 秒的体验，不依赖美术方向，也能为后续样片提供干净的对比基线。之后再按原第 2–5 步推进，并把 GAP-17/19/21/22 分别并入 QV-04/06/02/07。

## 6. 本次不能作出的结论

不能断言所有战斗只需按住普攻、所有角色均无动画、游戏缺乏全部剧情后果、当前存档损坏、音频质量差或性能不达标。开局失败截图也不足以证明难度失衡。上述结论均需对应调查任务补证据。

（复核补充）复核同样**不能**断言以下几点：

- 首战难度失衡：R04 是单次、刻意不闪避的样本。
- S 评级分布整体偏松：只观察到首战一次。
- 选择台离开后会丢失奖励：代码推断为需要重打，尚未实测。
- `E2E-T1-15` 存在产品缺陷：单独复跑 3/3 通过。

另外，headless 软件渲染下的帧数据不代表玩家机器的性能。
