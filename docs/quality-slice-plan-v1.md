# 《尘缘问道》首个品质验证版本任务表 v1

日期：2026-11-25。状态：任务包已规划，全部任务待开始，游戏代码与资产尚未修改。

关联：[体验标准](experience-standard-v1.md) · [现状差距](quality-gap-audit-20261125.md)。

## 1. 版本目标与范围

完成一段约 20–30 分钟的首次体验：**进入破庙 → 读懂并处理战斗 → 救下沈清禾 → 主动完成战后交谈 → 返回洞府 → 作出一次成长选择 → 在后续战斗中验证新打法。**

时长为试行目标，排除长时间停留，允许不同玩家阅读与探索速度不同。不能用强制等待、填充战斗或加快对白来机械凑时长。

本版本交付的是后续全游戏制作的品质参考。范围内先完成一个主角、一种普通敌人、一种与其应对不同的精英、一个关键 NPC、破庙和洞府相关区域、两个成长方向，以及配套界面和声音。优先复用现有角色与机制。

范围外：全地图重画、全角色动作重做、完整 3D 迁移、新增大型养成系统、多人系统、商业化、全剧情配音。已有其他系统保持可用，是否简化早期入口由体验调查决定，不删除玩家已获得内容。

不预先承诺“达到商业系列同等体量”。验收针对标准条款与这段实际体验。

## 2. 基线与工作方式

- 当前主工作树有未提交改动，且与远程分叉。实施前核对预期交付版本、现有独立工作树和差异；不自动 reset、覆盖、合并或推送。
- 本轮文档新增到当前仓库 `docs`；功能实现需建立独立 `codex/quality-<topic>` 分支/工作树，并通过 PR 交付。
- 确定基线时记录提交、工作树差异摘要、游戏文件校验值与资产清单。不能从旧提交创建分支后，误以为包含本次评估的未提交内容。
- 当前游戏为大型单文件，实施按依赖顺序推进；同一时段只有一个任务修改主游戏文件。不为本轮品质升级进行无必要的整文件重写或框架迁移。
- 角色动作选择序列帧还是骨骼动画，由样片质量、生产成本和运行效果决定；保持既有玩法状态与存档合同。
- 下列“责任”表示所需职能，不表示已创建团队、分派代理或获得人员预算。

## 3. 里程碑与依赖

| 里程碑 | 任务 | 退出条件 |
|---|---|---|
| M0：事实与规格 | QV-01 → QV-02 | 实施基线、可用验证路径、初始测量和目标画面规格齐全 |

| M2：完整旅程 | QV-06 → QV-07 → QV-08 → QV-09 | 救人、洞府、成长、再战及声音形成连续体验 |

允许资产制作在接口明确后与代码工作分开进行，但本计划默认顺序执行，不自动派发并行代理。若上游质量不成立，回到对应任务修复，不用新增系统补偿。

## 4. 可执行任务包

### QV-01 冻结实施基线并恢复可用验证路径

- 责任：工程/QA。优先级：P0。依赖：无。对应：GAP-12/13/14；TECH-01/03/04。
- 行动：核对主工作树与已有独立工作树，选定含本次有效改动的实现起点；查明 `tests/e2e/run.mjs` 缺失原因，确认哪些回归脚本实际存在；记录当前开场、战斗、存档与资产状态。
- 交付：基线记录、可执行命令清单、未覆盖项、60 秒典型战斗性能记录、首轮音频试听问题表。
- 验收：命令在目标工作树真实运行并保存结果；不能因为 npm 中存在名称就认定可用；没有脚本的覆盖使用明确替代方法且记录限制。若需迁移未提交修改，逐项保留来源与用户工作。

### QV-02 制作统一美术规格与实际尺寸目标画面

- 责任：美术/设计。优先级：P1。依赖：QV-01。对应：GAP-01/03/05/07；ART-01/02/03/05、UX-04。
- 行动：以破庙和洞府为样本，确定角色比例、镜头、光照、材质、配色、阴影、字体和图标规则；做静态常态、战斗高峰、洞府三种画面合成；列明素材来源与成本。
- 交付：视觉参考板、参数表、三张 1440×900 目标图、资产生产清单（角色状态/方向/锚点/命名/尺寸/许可）。目标图标记为设计稿，不伪装成实际运行截图。
- 验收：同一角色在两场景中尺度一致、接地可信、界面可读；评审记录选择与理由。通过后才扩大资产制作，不批量生产未经验证的风格。

### QV-03 完成主角与一种敌人的动作样片

- 责任：动画/工程。优先级：P1。依赖：QV-02。对应：GAP-02；MOT-01/02、ART-02/05。
- 行动：按状态表制作待机、移动、攻击起手/命中/收招、受击、闪避或对应位移、倒地；确定方向支持、脚底锚点和动作切换；接入现有战斗状态与判定。
- 交付：原始制作文件、导出资源、状态转换表、实际入口内动作录像、资源清单。
- 验收：主角和敌人逐状态检查；转向与连续输入不导致脚底跳动或动作卡死；10 次命中/挥空和闪避/受击对照可读；不能仅交动画播放器预览。

### QV-04 建立一场有明确决策的战斗

- 责任：战斗设计/工程。优先级：P1。依赖：QV-03。对应：GAP-08；PLAY-01/02/04、MOT-02。
- 行动：调查现有普攻、剑印、爆剑、闪避/识破的用途；为普通敌人确定“蓄力—攻击—恢复”节奏；精英增加一种不同的应对要求。优先调整既有机制而不是增加新键位。
- 交付：敌人行为与技能用途表、成功/错误应对录像、相同装备下的策略对比记录。
- 验收：玩家能从动作识别至少一次可利用的破绽；按机制处理在耗时、受伤或资源上有可解释优势；错误应对有可理解后果，不能只靠提高血量延长战斗。

### QV-05 重整战斗界面与情境教程

- 责任：交互/工程。优先级：P1。依赖：QV-04。对应：GAP-04/06/07；ART-04、UX-01/03/04/05。
- 行动：整理伤害、技能提示、成就、悬赏、教程的优先级；建立非紧急通知队列；减少覆盖行动区域的文字；让教程在战斗、撤退、安全区与返场之间正确切换。
- 交付：信息优先级表、实际界面、提示时间线、字号/对比度检查结果。
- 验收：战斗中同时最多 1 条非紧急浮层（试行）；关键动作无遮挡；延后奖励有明确入口且不会自动领取；鼠标/键盘可用，弹窗关闭焦点返回；安全区不再要求斩妖。

### QV-06 让救人事件产生可见变化

- 责任：叙事/美术/工程。优先级：P1。依赖：QV-05。对应：GAP-05/10；NAR-01/02/03、UX-02。
- 行动：建立沈清禾受困、获救、交谈、返回后的状态表；调整姿态、站位与少量对白；选择一个可在本章兑现的玩家决定；统一此次流程可见术语。
- 交付：短剧本、事件状态图、三个关键状态的运行截图、选择后果与持久化字段说明。
- 验收：遇险表现与台词一致；玩家主动推进；取消、离开、刷新不跳过选择也不重复发奖；若改存档，完成五场景验证；纯态度选项不得宣传为重大剧情分支。

### QV-07 将洞府改为有生活与使用关系的空间

- 责任：场景/交互/工程。优先级：P1。依赖：QV-06。对应：GAP-01/03/06；ART-02/03、NAR-01、UX-01/05。
- 行动：围绕休息、修剑/制作、人物交流与出行安排动线；减少普通 NPC 展示底座；补至少两处有用途的生活行为或环境互动；保留原功能入口可达性。
- 交付：空间路线图、场景与遮挡配置、人物行为列表、功能入口映射。
- 验收：走访各入口不穿越显著障碍；人物与设施尺度协调；获救角色有对应状态；老玩家仍能找到原功能，不能用美术重排造成内容丢失。

### QV-08 接通一次成长选择与后续试用

- 责任：系统/战斗/工程。优先级：P1。依赖：QV-04/07。对应：GAP-09/10；PLAY-03/04/05、UX-02、TECH-02。
- 行动：调查现有成长入口，优先从已有剑印/爆剑机制形成两个方向。例如“增强打断”与“扩散剑印”仅为候选，需行为和成本验证后确定；安排有不同敌人配置的试用战斗。
- 交付：成长选择说明、成本/效果/适用情境表、两个方向的实战对照、资产变化记录。
- 验收：玩家主动选择和消费；两个方向各有适用情境；重复进入和刷新无额外收益；选择后立即可体验差异；兼容旧存档已有技能，不强行清除或重置。

### QV-09 完成这一段旅程的声音与节奏

- 责任：声音/工程。优先级：P1。依赖：QV-08。对应：GAP-11；AUD-01/02、MOT-02、PLAY-04。
- 行动：依据 QV-01 试听补齐关键脚步、攻击、接触、受击、雨声和场景转场；处理音乐与对白/危险音效的相对音量；校验静音、音量偏好、首次解锁与降低动态效果。
- 交付：音频事件表、来源/许可/源文件、混音参数、实机带声录像及耳机/扬声器试听记录。
- 验收：声音与事件同步，无持续掩盖提示的音层、明显爆音或突兀截断；静音仍可完成战斗；未试听不标记完成。

### QV-10 完成整段体验与兼容回归

- 责任：工程/QA。优先级：P0（交付）。依赖：QV-09。对应：GAP-12/13/14；TECH-01/02/03/04、ART-05。
- 行动：直接文件与静态 HTTP 验证真实入口；检查完整旅程、键鼠、失败撤退、重复进入、声音控制、降低动态效果、资源加载及素材清单。执行 QV-01 确认可用且与变更相关的回归，完成项目要求的最终检查。
- 交付：验证矩阵、实际命令及日志、完整流程录像、性能前后对比、已知限制。
- 验收：涉及存档的路径覆盖五场景；多标签页案在专用共享存储上下文中运行；旧档为合成测试数据；读取失败保原文、写入失败不报成功。未测、失败、通过分开记录；发现问题返回对应任务修复并定向复测。

### QV-11 外部试玩与品质评审

- 责任：产品/QA/试玩参与者。优先级：P1。依赖：QV-10。对应：全部样片标准。
- 行动：安排 3–5 名未参与开发的人试玩；仅给正常游戏入口和基本任务，不在途中讲解设计答案。记录操作困惑、战斗调整、故事复述与成长选择理解。游戏完成后再询问感受。
- 交付：匿名试玩记录、阻碍位置、六维品质评分及证据、修复优先级。没有真实参与者时明确标为待执行，不以代理或脚本替代人类试玩结论。
- 验收：标准文档的硬约束与品质闸门满足；预计 20–30 分钟的流程未靠重复劳动凑时长；不达标项有具体修复与复测结果。参与者尚未安排不应阻止前序制作工作。

### QV-12 固化标准并安排全游戏推广

- 责任：产品/工程/美术。优先级：P2。依赖：QV-11 通过。对应：全部标准维护。
- 行动：将验证过的色彩、比例、动画规则、战斗节奏、声音和资源预算写回标准；保留实际样片作为参考；重新扫描其余章节，按复用价值和体验影响拆任务。
- 交付：体验标准修订版、可运行品质样片、制作模板、全游戏推广待办、PR/交付说明。
- 验收：每个新增待办都有对应标准、场景、范围和证据要求；没有把样片通过写成全游戏通过；交付如实说明剩余缺口。

## 6. 每项任务的完成定义

必须同时具备：已完成的玩家体验变化、所引用条款的实际证据、涉及数据的兼容说明、必要自动化与真实入口验证、残留问题、可审查差异。只有代码、只有设计图、只有通过数量或只有一句“已优化”均不算完成。

PR 模板：问题与前后行为 → 对应标准/差距/任务编号 → 修改范围与数据影响 → 实际验证及证据 → 未验证范围与后续责任。文档状态、任务状态和实际代码必须一致。
