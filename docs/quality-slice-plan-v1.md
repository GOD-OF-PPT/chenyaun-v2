## 1. 版本目标与范围

完成一段约 20–30 分钟的首次体验：**进入破庙 → 读懂并处理战斗 → 救下沈清禾 → 主动完成战后交谈 → 返回洞府 → 作出一次成长选择 → 在后续战斗中验证新打法。**

时长为试行目标，排除长时间停留，允许不同玩家阅读与探索速度不同。不能用强制等待、填充战斗或加快对白来机械凑时长。

本版本交付的是后续全游戏制作的品质参考。范围内先完成一个主角、一种普通敌人、一种与其应对不同的精英、一个关键 NPC、破庙和洞府相关区域、两个成长方向，以及配套界面和声音。优先复用现有角色与机制。

范围外：全地图重画、全角色动作重做、完整 3D 迁移、新增大型养成系统、多人系统、商业化、全剧情配音。已有其他系统保持可用，是否简化早期入口由体验调查决定，不删除玩家已获得内容。

不预先承诺“达到商业系列同等体量”。验收针对标准条款与这段实际体验。

## 2. 基线与工作方式

- 当前主工作树有未提交改动，且与远程分叉。实施前核对预期交付版本、现有独立工作树和差异；不自动 reset、覆盖、合并或推送。
- 本轮文档新增到当前仓库 `docs`；功能实现需建立独立 `codex/quality-<topic>` 分支/工作树，并通过 PR 交付。

## 4. 可执行任务包

### QV-00 首战快修（v1.1 新增，v1.2 按决策记录细化）

- 责任：工程/交互/战斗。优先级：P1。依赖：无，可与 QV-01 剩余部分并行。对应：GAP-15～20；UX-03、UX-05、UX-06、AUD-02、PLAY-01、PLAY-03。决策依据见 §8（D-06～D-09、D-12）。
- 背景：复核在当前 main 上实测到几个问题，都出现在每位新玩家的前 60 秒，而且都不依赖美术方向：
  - 战斗键 Space 会推进剧情对白；
  - 清场瞬间多类信息同时弹出，战斗浮字在对白期间冻结，还会残留到洞府；
  - 普通连点就能拿到 S 评级，而闪避要到致命危招之后才教；
  - 谢礼选择不入存档；
  - 音频偏好刷新后丢失。

  先修好这些，中期试玩（§8 D-10）观察到的才是真正需要美术和战斗设计解决的问题，不会被低成本缺陷干扰。
- 按风险拆成 3 个独立的 `codex/` 分支和 PR，可以并行开发、分别合入：

  **PR① 交互快修**（GAP-15/16/20，S 级）
  1. **输入隔离**：对白只能用 Enter 或鼠标点击“继续”推进。对白期间不把 Space 当作确认键；E 已绑定“本命法宝剑域”，也不使用。对白或选择出现后 400 ms 内忽略推进输入；战斗中已按下的键须松开后重新按下才算确认。焦点仍落在“继续”按钮上，按钮标注“Enter 继续”。同步排查其他会自动聚焦按钮的弹窗。
  2. **清场收束**：固定顺序为“清场 → 约 0.8 s 收束（浮字淡出、横幅合并为 1 行、连击面板收起、雨声回落）→ 对白 → 对白结束后出现玉莲台选择”。悬赏和评级改为对白后的一行汇总。切换场景（含 `enterSanctumHub`）时清空全部战斗浮层，并重置连击面板。开启 reducedMotion 时不做淡出动画，直接切换。
  3. **声音开关**：“战斗音效”按钮改名为“全部声音”。静音和 BGM 开关与分轨音量一起持久化到版本化键；旧键缺失时取当前默认值，写入失败时只提示，不影响游戏。

  **PR② 首战教学与评级**（GAP-17/18，M 级，涉及战斗规则）
  1. **一闪情境教学**：第一次出现红色危招前摇时短暂慢放，并弹出“空格 · 一闪”提示。开启 reducedMotion 时不慢放，只给提示。
  2. **首次保底**：首战中第一次被危招命中时保留 1 点血，之后按正常规则。这不构成硬门槛（D01）。
  3. **评级计分来源**：S/A/B/C 的增益数值不变（`combat-stats.mjs` `getStyleRankSpec`），只调整计分来源，让分数主要来自识破、完美闪避和破势。单纯连点最高到 B–A。
  4. 跑 `scripts/eval-combat-matrix.mjs`、`design.md` 的 84 组矩阵和 `audit-economy`，确认后续卷次的评级分布和掉落没有失衡。

  **PR③ 待选谢礼入档**（GAP-19，M 级，涉及存档结构）
  1. 修改前先实测现状，作为“改前”证据：未选谢礼时离开、回洞府、刷新、再回破庙，分别会发生什么。
  2. “已救未选”状态写入存档。离开后在洞府和回到破庙时都能继续选择，不替玩家代选。
  3. 旧档兼容：只有“已救下沈清禾”且“没有任何谢礼选择记录”时，才补发一次选择；已选过的旧档不得重复发放。
  4. 覆盖 AGENTS.md 的五类场景：开局、旧档续玩、刷新、写入失败（显示失败并保留原档）、多标签页竞争（不重复领取）。

- 交付：`src/runtime` / `src/rules` 改动及 `npm run build` 产物；每个 PR 新增对应的 E2E 用例；修复前后截图，复用复核证据包的 R02、R03、R04、R05 作为“前”。
- 验收：
  - 清场瞬间连按 Space、E、左键各 10 次：对白不跳句，谢礼不被误选；
  - 保护期过后，Enter 和点击都能推进对白，焦点可辨认；
  - 清场到对白之间可见收束，回洞府后没有战斗浮字或连击面板；
  - 静音和 BGM 关闭状态在刷新后保持；
  - 原地按住左键：第一次危招不致死，并出现一闪提示；
  - 只连点、不闪避时评级不超过 A；
  - 谢礼在离开、刷新后仍可选，五类存档场景通过；
  - 全部现有命令（见 QV-10）通过。

## 6. 每项任务的完成定义

必须同时具备：已完成的玩家体验变化、所引用条款的实际证据、涉及数据的兼容说明、必要自动化与真实入口验证、残留问题、可审查差异。只有代码、只有设计图、只有通过数量或只有一句“已优化”均不算完成。

PR 模板：问题与前后行为 → 对应标准/差距/任务编号 → 修改范围与数据影响 → 实际验证及证据 → 未验证范围与后续责任。文档状态、任务状态和实际代码必须一致。
